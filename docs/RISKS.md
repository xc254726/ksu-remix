# 风险与合规

## 变砖风险

内核级改动失败的表现按严重程度：

| 现象 | 原因 | 恢复 |
|---|---|---|
| 卡 logo / 无限重启 | 内核初始化失败 | `fastboot flash boot <原厂img>` |
| 能开机，掉触控/声音/相机/WiFi | vendor 模块 vermagic 或 CRC 不匹配 | 同上，或重编时对齐 MODVERSIONS |
| 黑屏无任何输出 | 页大小错误（4k↔16k） | 同上 |
| 连 fastboot 都进不去 | 极罕见，通常是刷错分区 | 深度刷机工具 / 售后 |

**底线要求**：

1. 动手前把原厂 `boot.img` 备份到电脑和网盘各一份
2. 确认 Bootloader 已解锁，且知道怎么进 fastboot（电源 + 音量下）
3. 先只刷一个槽（`boot_a`），验证能开机再刷另一个

## 版本错配

厂商公开源码只同步到某个固件版本。设备系统版本高于源码版本时：

- `Makefile` 的 `6.6.66` 对不上 → `make config` 会告警，`STRICT_VERSION=1` 时直接中止
- 强行编出来也能开机，但内核与固件不配套，行为不可预期（掉基带、掉快充协议、相机异常）

这不是"再改改代码就能解决"的问题，只能等厂商更新源码，或从设备 dump 当前内核做对照。

## GPL 合规

KernelSU 内核部分 GPL-2.0-only，其余 GPL-3.0-or-later；Linux 内核 GPL-2.0。

对外发布二改包时必须做到：

- 提供完整对应源码（含你的修改），或给出可获取的有效途径
- 保留原作者版权声明与许可证文本
- 不得闭源分发、不得加限制性条款
- 明确标注"基于 KernelSU / 某某内核源码修改"，不要抹掉来源

只自己用则不受分发条款约束。

## 不要做的事

- 不要给未解锁 Bootloader 的设备提供刷机包——刷不进去，只会引来无意义的求助
- 不要声称"通杀所有机型"。vermagic 是逐字符匹配的，跨机型必然失效
- 不要在包里塞来源不明的二进制（尤其声称"破解检测"的闭源模块）
